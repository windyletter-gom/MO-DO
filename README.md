# 모두 (MO DO) v3.0

**모두(MO DO)** — MOA + DO, "모두 함께 일한다". 모아교육그룹 업무협업 플랫폼.

## 로그인 / 계정
- 첫 화면은 **로그인 페이지**입니다. **아이디 = 직원 이메일 주소**, **최초 비밀번호 = `1234`**(전 직원 공통)입니다.
- 로그인 후 우측 상단 **개인 설정**에서 본인 비밀번호를 변경할 수 있습니다. (관리자는 필요 시 특정 계정을 1234로 초기화 가능: `/api/reset-password`)
- **권한**: 이원행 이사(최고관리자)는 당분간 모든 메뉴·전체 팀을 열람합니다. **팀장·사원은 본인 소속 팀 워크스페이스만** 접근합니다.
- 세션은 브라우저에 저장되어 종료 후 재접속 시 유지되며, **로그아웃**으로 해제합니다.

## 실행 및 다중 사용자 운영 방법 (중요)
- **여러 명이 함께 쓸 때는 '한 대'의 PC에서만 `start.bat`을 실행**하고, 나머지 인원은 브라우저에서 그 PC의 주소(`http://<서버PC IP>:8000`)로 접속하세요. 실행 시 콘솔 창에 접속 주소가 표시됩니다.
- 네트워크 공유 폴더에 두고 **각자 실행**하는 방식은 SQLite 파일 잠금이 불안정해 데이터 충돌·유실 위험이 있으므로 권장하지 않습니다(한 대 서버 방식 권장).
- **데이터 영속성**: DB 저널을 네트워크 파일시스템에서 안전한 DELETE 모드로 변경했습니다. 프로그램을 종료했다 다시 열어도 그동안 쌓인 데이터가 그대로 유지됩니다. (기존 WAL 모드는 공유 폴더에서 변경분이 유실되는 문제가 있었습니다.)

## DB 초기화 (테스트 종료 후 실 사용 전)
프로그램을 **완전히 종료한 상태**에서 아래 배치를 실행합니다. 두 경우 모두 실행 전 자동 백업(`data/moa_work_backup_*.db`)이 생성됩니다.
- **`초기화_운영시작.bat`** — 부서·팀·구성원 계정은 그대로 두고, 테스트로 쌓인 **활동 데이터(업무·프로젝트·업무지시·공지·검수·일정·댓글·이력 등)만 삭제**합니다. 실제 업무용 빈 상태로 시작할 때 사용하세요. (초기화 이후에는 예시/데모 데이터가 다시 생기지 않습니다.)
- **`초기화_완전초기화.bat`** — DB를 삭제하고 다음 실행 시 **기본(데모 포함) 상태로 새로 생성**합니다. 처음 배포 상태로 되돌릴 때 사용하세요.

## v3.0 개선 (사용자 피드백 1·2·3차 반영)
- **담당자 다중 지정(1차-1)**: 업무 등록·상세에서 담당자를 여러 명 지정하고 역할(기획담당/디자인담당 등)을 부여. 공동 담당자도 해당 업무를 열람 가능(`task_assignees`).
- **업무 수정 확대(1차-2)**: 업무 상세에서 완료 방식(검토·컨펌형↔완료보고형), 검토·승인선(승인자 추가/삭제·순서), 담당자·공동담당자까지 변경 가능.
- **팝업 배경 클릭 닫기(1차-3)**: 모달의 빈 배경을 클릭해도 닫히도록 추가.
- **칸반 [막힘] 보드(1차-4)**: 업무관리 칸반에 막힘(BLOCKED) 단계 컬럼 추가.
- **반려(거절) 흐름(1차-5)**: 승인자가 검토 내역에서 '반려'하면 업무가 진행중으로 되돌아가고 승인현황 '반려' 칸에 집계됩니다(기존 흐름 확인).
- **프로젝트 업무 가시성 제한(1차-6)**: 프로젝트 세부 업무는 TFT 참여자·참여팀에게만 노출(팀 공개 규칙으로 새어나가지 않도록 분리).
- **승인자 선택 버그(3차-2)**: 작성자(팀장)가 본인을 승인자로 지정할 때 '1명 이상 선택' 오류로 막히던 문제 수정(작성자는 승인자 가능, 실제 요청 시 요청자/담당자만 자동 제외).
- **승인현황 정리(3차-3)**: 업무 승인 현황을 검토·컨펌형만 대상으로 제한(완료보고형이 '상위 결재 대기' 등에 잘못 노출되던 문제 해소).
- **검색 화면(3차-1)**: 팀·상태 구분값을 검색어 앞으로 배치, placeholder에서 '팀 검색' 문구 제거.
- **캘린더(2차-1,2)**: 진입 시 현재 월 표시(7월 고정 버그 수정). 개인(PERSONAL) 일정은 본인에게만 노출.
- **팀 워크스페이스 수정/삭제(2차-3)**: 라이브특강·프로모션·B2B·사이트운영·회의록·독서토론·체크리스트·자료/링크에 수정·삭제 추가. 구매내역의 '부서 전체' 목록은 이사·관리자에게만 노출(타 팀 노출 문제 해소). 독서토론 상태는 예정/완료로 단순화, 체크리스트에 '완료' 버튼 추가.

## v3.0 반영 (수정 SB ver1.2 · 슬라이드 4·5·10·13)
- **업무지시 센터 개선(슬라이드4)**: 상단 '+업무지시 작성' 버튼과 중복되던 하단 인라인 '내용 작성' 폼 삭제. 업무지시 모달을 **수신자 다중 선택**(검색·전체선택 지원)과 **파일 첨부**(캡쳐본·문서 등 최대 5개, `directive_files`) 지원으로 개편. 다수 구성원에게 동일 지시를 한 번에 전달(수신자별 개별 지시 생성).
- **오늘의 업무 리스트화(슬라이드5)**: 홈 '오늘의 업무' 리스트 항목 클릭 시 업무 상세 팝업이 뜨지 않도록 수정(리스트 조회 전용).
- **업무 삭제(슬라이드10)**: 업무 상세에 '업무 삭제' 버튼 추가(`DELETE /api/tasks/{id}`, 담당·작성자·관리자만). 삭제 시 댓글·이력·검토 내역까지 정리. 업무명·설명 등 전체 필드 수정은 기존 저장으로 동작.
- **프로젝트 삭제·보류(슬라이드13)**: 프로젝트 상세에 '보류'·'삭제' 버튼 추가. **보류**(`PATCH status=HOLD`)는 진행 목록에서 내려가고 프로젝트 히스토리에 '보류'로 표시, **삭제**(`DELETE /api/projects/{id}`)는 세부 업무·결재선·구성원까지 완전 제거(히스토리에도 안 남김).

## v3.0 반영 (수정 SB ver1.0 후속)
- **업무 상세에 검토·승인선 표시**: 검토·컨펌형 업무의 상세 모달에 결재선(승인 순서)을 추가. 각 승인자를 순번·소속과 함께 나열하고 승인/반려/자동 제외/대기 상태와 '현재 차례'를 표시. 완료보고형은 "별도 승인선 없이 완료보고로 종료" 안내를 명시. 프로젝트 없는 개별 업무의 상세에 'null'로 표기되던 문제도 '개별 업무'로 수정.
- **검토·컨펌형 예시 업무 시드**: 기존 시드 업무가 전부 완료보고형이라 승인 흐름을 테스트할 데이터가 없던 문제 해결. 결재선(팀장→이사)을 가진 예시 검토·컨펌형 업무 2건을 시드에 추가(팀장 차례 1건, 이사 컨펌 대기 1건). REVIEW 업무가 하나도 없을 때만 1회 생성되어 기존 DB에도 다음 실행 시 반영.
- **업무 승인 현황 — 팀장·이사 결재 분리**: 팀장 이상 직급에는 승인 현황 상단에 **'내가 처리' / '상위 결재 대기'** 토글을 추가(일반 구성원 화면은 변경 없음). '내가 처리'는 지금 내가 승인·처리할 차례, '상위 결재 대기'는 내가 상신했거나 **이미 승인해 나보다 위 단계(상사)** 결재를 기다리는 업무. 승인 순서를 반영해 **아직 내 차례가 아닌 하위 단계 대기 건은 두 버킷에서 제외**(이사가 볼 때 팀장 단계 대기 건이 '상위 결재 대기'에 섞이지 않음)하고, 제외된 건수는 안내 문구로 표시. 각 토글 안에서 대기/반려/완료 3열 유지.
- **프로젝트 히스토리 = 업무 히스토리 동일화**: 프로젝트 히스토리 탭을 업무 히스토리와 **동일한 좌측 목록 + 우측 타임라인 UI/기능**으로 재구성. 검색(프로젝트명·PM·팀)·상태(진행중/완료/승인대기/반려)·팀·기간 필터 지원(`/api/project-history`, `/api/project-history/{id}`). 타임라인은 프로젝트 등록 → TFT 구성원 합류 → 개설 승인/반려 → 세부 업무 등록·완료를 시간순 표시.
- **상품·가격 관리 기능화(슬라이드2 후속)**: 기존 등록 전용이던 상품 모듈에 **수정·삭제·상태변경·랜딩 노출(노출/제외) 관리** 추가(`PATCH/DELETE /api/planning/products/{id}`). 평생 상품 단독 운영, 기본/심화→정규 첨삭반, 전병호 기술사 강의 랜딩 제외·종료를 앱에서 직접 관리. 가격은 화면에서 입력·수정.

## 배포본 반영 (홈·MCC·관리자)
- **최고관리자 권한**: 정해근·이원행 두 사람에게 SUPER_ADMIN 부여. 서버·프론트의 관리자 판별을 `isSuperAdmin()`(정해근·이원행·SUPER_ADMIN)으로 통일.
- **홈 화면 재구성**: 인사말 → 업무지시 센터 → **공지사항(신규)** → 진행 중인 업무 KPI → WORKSPACE FLOW → 오늘의 업무/우선 처리 순으로 배포본 구조에 맞춤. 이원행 이사의 개인 업무지시(EXECUTIVE DIRECTIVE) 기능은 그대로 보존.
- **공지사항(Company Notice)**: `company_notices` 테이블 + `GET/POST/DELETE /api/notices` 신설. 관리자만 등록/삭제, 중요 고정·분류 지원. 홈에 공지 카드 노출. 예시 공지 3건 시드.
- **MCC 교재·법령 검수**: 기존 모듈(개요 KPI·검수현황·항목 비교·진행률)에 실데이터 예시 3건(가스 KGS·소방 NFTC·KGS FU551)과 항목별 비교결과를 시드하여 화면이 채워지도록 보강.
- **업무관리·이력보기**: 기존 화면(칸반 흐름 + 내업무/우리팀/관련팀/부서공유/검토대기/완료보고/업무이력 스코프)이 배포본 구조와 동일하여 유지.

## 진단보고서 반영 (이전 단계 유지)

## 🔴 치명적 수정
- **데이터센터 상세보기 500 오류 / 삭제 미작동 해결**: `do_GET`·`do_DELETE`에 잘못 복사되어 들어간 죽은 핸들러(요청 본문 `x` 참조)를 제거. 상세조회는 정상 GET 라우트로, 삭제는 실제 DELETE 라우트로 도달합니다.
- **경로 조작(Path Traversal) 차단**: `/static/`·`/uploads/` 정적 서빙에 `safe_join()`을 도입해 상위 경로(`../`) 탈출을 403으로 차단. 소스코드·DB 파일 유출 경로를 막았습니다.
- **`init_db.py` 문법 오류 복구**: 47행의 닫히지 않은 문자열(`c.execute("`)을 `c.executescript(""" ... """)`로 수정. DB 파일이 없을 때 자동 재생성이 정상 동작합니다.
- **요청/문의 종결 기능 추가**: `PATCH /api/requests/{id}`(status 변경) 신설. 프론트 대화창에 "완료 처리" 버튼 추가. 처리한 요청이 대시보드 카운트에 영구 누적되던 문제 해소.

## 🟠 중요 수정
- **외래키(FK) 제약 추가**: 신규 설치(init_db) 시 divisions·teams·users·projects·tasks·requests·activity_logs·task_comments·notifications·directives·directive_replies·request_replies에 참조 무결성 적용. `PRAGMA foreign_key_check` 위반 0건 검증.
- **인덱스 추가**: tasks(assignee/team/project/status/reviewer/created_by), task_approvals, notifications, requests, consultation_logs, data_board 등 조회·조인 핵심 컬럼에 인덱스 생성(`ensure_schema`에서 기존 DB에도 안전 적용).
- **`/api/export` 보호 + 민감정보 마스킹**: 관리자(SUPER_ADMIN/DIVISION_ADMIN)만 호출 가능. 구매 비밀번호 힌트·계정ID는 `***`로 마스킹.
- **업로드 크기 제한**: 요청 본문 최대 30MB 제한으로 메모리 폭주 방지.
- **SQLite WAL 모드 + busy_timeout**: 동시 접근 시 `database is locked` 완화.

## 🟡 개선
- 스키마 정의 정합성 정비(init_db와 ensure_schema 불일치 축소), 버전 표기 v2.1.6로 통일.

## 남은 권장 사항 (다음 단계)
- **로그인/세션 기반 인증 도입**: 현재 권한 판단은 여전히 클라이언트가 보낸 `actor_id`/`viewer_id`에 의존합니다. 여러 명이 접속하는 환경이라면 서버 세션 인증으로 전환하고 `이름=='정해근'` 하드코딩 판별을 role 기반으로 교체해야 합니다.
- 기존 운영 DB에 FK를 소급 적용하려면 테이블 재생성 마이그레이션이 필요합니다(현재 파일은 신규 설치분에만 FK 적용, 기존 DB는 인덱스만 소급 적용).

## 실행 방법
Windows에서 `start.bat` 실행(Python 필요). 표준 라이브러리만 사용하며 외부 패키지 설치가 필요 없습니다.
